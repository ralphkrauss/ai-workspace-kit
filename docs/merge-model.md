# Merge Model

The installer migrates existing setup into a layered AI workspace. It should not
replace files blindly.

## Layering

Use the narrowest layer that fits the content:

| Layer | Purpose |
| --- | --- |
| `AGENTS.md` | Short repository-wide instructions loaded by most tools |
| nested `AGENTS.md` | Directory-specific rules |
| `.agents/*.md` | Longer reference docs |
| `.agents/rules/*.md` | Cross-cutting rules activated by file patterns |
| `.agents/skills/*/SKILL.md` | Repeatable workflows |
| tool wrapper files | Tool-specific imports, MCP notes, or generated projections |

## Existing File Strategy

1. Read the existing file.
2. Identify sections that are universal, directory-scoped, tool-specific, or
   workflow-specific.
3. Preserve project-specific information.
4. Move reusable workflow material into skills only when it is truly procedural.
5. Move long explanations into docs and keep short pointers in always-loaded
   files.
6. Import useful manual Cursor guidance from `.cursor/rules/` or `.cursorrules`
   into `.agents/rules/` before generating `.cursor/`.
7. Keep comments about generated files in generated directories.

## Conflict Handling

Ask the user when:

- existing instructions contradict the kit defaults
- two tools expect incompatible formats
- a generated projection is already manually edited
- task commands cannot be inferred
- hooks or MCP config already exist and the right merge is unclear

## Generated Files

Generated files should contain a short header:

```text
Generated from .agents/... by scripts/sync-ai-workspace.mjs.
Do not edit this file directly.
```

The canonical source remains under `.agents/`.

Tool-specific projection directories such as `.cursor/` may be ignored by git.
Do not treat them as canonical storage; regenerate them from `.agents/` during
local setup or cloud-agent bootstrap when the selected tool needs them.

## Migration Report

At the end of migration, report:

- files created
- files modified
- existing files preserved unchanged
- sections moved between layers
- unresolved conflicts
- follow-up questions
